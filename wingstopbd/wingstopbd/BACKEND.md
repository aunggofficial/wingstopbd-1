# Wing Stop BD - Complete Backend Setup Guide\n\n## Overview\n\nThis guide covers the complete setup of the Wing Stop BD backend API server, database, and integration with Stripe for payments.\n\n**Technology Stack:**\n- **Runtime:** Node.js 16+\n- **Framework:** Express.js\n- **Language:** TypeScript\n- **Database:** PostgreSQL\n- **Payment:** Stripe API\n- **Authentication:** JWT (JSON Web Tokens)\n\n---\n\n## Prerequisites\n\n- Node.js 16+ installed\n- PostgreSQL 12+ installed and running\n- Stripe account (https://stripe.com)\n- Git for version control\n- npm or yarn package manager\n\n---\n\n## Step 1: Database Setup\n\n### 1.1 Create PostgreSQL Database\n\n```bash\n# Connect to PostgreSQL\nsudo -u postgres psql\n\n# Create database and user\nCREATE DATABASE wingstopbd;\nCREATE USER wingstop_user WITH PASSWORD 'your_secure_password';\nALTER ROLE wingstop_user SET client_encoding TO 'utf8';\nALTER ROLE wingstop_user SET default_transaction_isolation TO 'read committed';\nALTER ROLE wingstop_user SET default_transaction_deferrable TO on;\nALTER ROLE wingstop_user SET default_time_zone TO 'UTC';\nGRANT ALL PRIVILEGES ON DATABASE wingstopbd TO wingstop_user;\n\\q\n```\n\n### 1.2 Import Database Schema\n\n```bash\n# Connect to the database and import schema\npsql -U wingstop_user -d wingstopbd -f wingstopbd-database-schema.sql\n```\n\n### 1.3 Verify Database\n\n```bash\n# Connect and check tables\npsql -U wingstop_user -d wingstopbd\n\\dt  # List all tables\n\\q  # Exit\n```\n\n---\n\n## Step 2: Backend Project Setup\n\n### 2.1 Create Project Directory\n\n```bash\nmkdir wingstopbd-backend\ncd wingstopbd-backend\n```\n\n### 2.2 Initialize Node Project\n\n```bash\nnpm init -y\n```\n\n### 2.3 Install Dependencies\n\n```bash\nnpm install express cors dotenv jsonwebtoken bcrypt pg stripe uuid\nnpm install --save-dev typescript @types/express @types/node ts-node nodemon\n```\n\n### 2.4 Create TypeScript Configuration\n\n**tsconfig.json:**\n```json\n{\n  \"compilerOptions\": {\n    \"target\": \"ES2020\",\n    \"module\": \"commonjs\",\n    \"lib\": [\"ES2020\"],\n    \"outDir\": \"./dist\",\n    \"rootDir\": \"./src\",\n    \"strict\": true,\n    \"esModuleInterop\": true,\n    \"skipLibCheck\": true,\n    \"forceConsistentCasingInFileNames\": true,\n    \"resolveJsonModule\": true,\n    \"declaration\": true,\n    \"declarationMap\": true,\n    \"sourceMap\": true\n  },\n  \"include\": [\"src/**/*\"],\n  \"exclude\": [\"node_modules\"]\n}\n```\n\n### 2.5 Create Project Structure\n\n```bash\nmkdir -p src/{routes,middleware,models,utils,controllers}\ntouch src/server.ts\n```\n\n### 2.6 Copy Backend Server Code\n\nCopy the content from `wingstopbd-backend-server.ts` to `src/server.ts`\n\n### 2.7 Update package.json Scripts\n\n```json\n{\n  \"scripts\": {\n    \"dev\": \"nodemon --exec ts-node src/server.ts\",\n    \"build\": \"tsc\",\n    \"start\": \"node dist/server.js\",\n    \"test\": \"jest\"\n  }\n}\n```\n\n---\n\n## Step 3: Environment Configuration\n\n### 3.1 Create .env File\n\n```bash\ncp wingstopbd-backend-env.txt .env\n```\n\n### 3.2 Update .env with Your Values\n\n```env\n# Database\nDB_HOST=localhost\nDB_PORT=5432\nDB_USER=wingstop_user\nDB_PASSWORD=your_secure_password\nDB_NAME=wingstopbd\n\n# JWT\nJWT_SECRET=your_very_secure_random_string_here\n\n# Stripe (Get from https://dashboard.stripe.com/apikeys)\nSTRIPE_SECRET_KEY=sk_test_xxxxx\nSTRIPE_PUBLISHABLE_KEY=pk_test_xxxxx\nSTRIPE_WEBHOOK_SECRET=whsec_xxxxx\n\n# Frontend\nFRONTEND_URL=http://localhost:5173\n```\n\n### 3.3 Add .env to .gitignore\n\n```bash\necho \".env\" >> .gitignore\necho \"node_modules/\" >> .gitignore\necho \"dist/\" >> .gitignore\n```\n\n---\n\n## Step 4: Stripe Configuration\n\n### 4.1 Get Stripe API Keys\n\n1. Go to https://dashboard.stripe.com/apikeys\n2. Copy your **Secret Key** and **Publishable Key**\n3. Add them to your `.env` file\n\n### 4.2 Set Up Webhook\n\n1. Go to https://dashboard.stripe.com/webhooks\n2. Click \"Add endpoint\"\n3. Enter your webhook URL: `https://your-domain.com/api/webhook/stripe`\n4. Select events: `checkout.session.completed`, `charge.refunded`\n5. Copy the signing secret and add to `.env`\n\n### 4.3 Test Stripe Integration\n\nUse Stripe test cards:\n- **Success:** `4242 4242 4242 4242`\n- **Decline:** `4000 0000 0000 0002`\n\n---\n\n## Step 5: Running the Backend\n\n### 5.1 Development Mode\n\n```bash\nnpm run dev\n```\n\nServer will start on `http://localhost:3001`\n\n### 5.2 Production Build\n\n```bash\nnpm run build\nnpm start\n```\n\n---\n\n## API Endpoints Reference\n\n### Authentication\n\n**POST /api/auth/register**\n```json\n{\n  \"email\": \"user@example.com\",\n  \"password\": \"secure_password\",\n  \"full_name\": \"John Doe\",\n  \"phone_number\": \"+880191234567\",\n  \"role\": \"customer\"\n}\n```\n\n**POST /api/auth/login**\n```json\n{\n  \"email\": \"user@example.com\",\n  \"password\": \"secure_password\"\n}\n```\n\n### Menu\n\n**GET /api/menu**\n- Get all available menu items\n\n**GET /api/menu/category/:category**\n- Get items by category (wings, burgers, coffee, drinks)\n\n### Orders\n\n**POST /api/orders** (Requires authentication)\n```json\n{\n  \"items\": [\n    {\n      \"menu_item_id\": \"uuid\",\n      \"quantity\": 2,\n      \"discount_percentage\": 10\n    }\n  ],\n  \"delivery_address\": \"123 Main St\",\n  \"notes\": \"No onions\"\n}\n```\n\n**GET /api/orders** (Requires authentication)\n- Get orders for current user\n\n**GET /api/orders/track/:orderNumber/:phone**\n- Track order by order number and phone (no auth required)\n\n**PATCH /api/orders/:orderId/status** (Staff/Admin only)\n```json\n{\n  \"status\": \"preparing\",\n  \"eta_minutes\": 30\n}\n```\n\n**PATCH /api/orders/:orderId/delivered** (Driver only)\n- Mark order as delivered\n\n**PATCH /api/orders/:orderId/cancel** (Customer only)\n- Cancel order if status is 'new'\n\n### Promos\n\n**GET /api/promos**\n- Get all active promos\n\n**POST /api/promos** (Staff/Admin only)\n```json\n{\n  \"name\": \"Weekend Special\",\n  \"discount_percentage\": 15,\n  \"discount_type\": \"category\",\n  \"target_category\": \"wings\",\n  \"start_date\": \"2025-01-01T00:00:00Z\",\n  \"end_date\": \"2025-01-31T23:59:59Z\"\n}\n```\n\n### Checkout\n\n**POST /api/checkout** (Requires authentication)\n```json\n{\n  \"orderId\": \"uuid\"\n}\n```\n\nReturns Stripe checkout session URL\n\n### Refunds\n\n**POST /api/refunds** (Requires authentication)\n```json\n{\n  \"orderId\": \"uuid\",\n  \"reason\": \"Changed my mind\"\n}\n```\n\n**PATCH /api/refunds/:refundId/process** (Admin/Staff only)\n```json\n{\n  \"status\": \"processed\"\n}\n```\n\n---\n\n## Database Models\n\n### Users\n- Stores customer, staff, driver, and admin accounts\n- Roles: customer, staff, driver, admin\n- Password hashed with bcrypt\n\n### Menu Items\n- Restaurant menu with categories\n- Categories: wings, burgers, coffee, drinks\n- Availability flag for active items\n\n### Orders\n- Customer orders with status tracking\n- Statuses: new, confirmed, preparing, out_for_delivery, delivered, cancelled\n- Linked to customer, driver, and staff\n\n### Order Items\n- Line items for each order\n- Tracks quantity, price, and discounts\n\n### Promos\n- Discount promotions by item or category\n- Date-based activation\n- Percentage-based discounts\n\n### Refunds\n- Refund requests and processing\n- Stripe integration for payment refunds\n- Status tracking: pending, approved, processed, failed\n\n### Notifications\n- Order updates for customers\n- New order alerts for staff\n- Refund notifications\n\n---\n\n## Authentication & Authorization\n\n### JWT Token\n\nAll authenticated endpoints require:\n```\nAuthorization: Bearer <token>\n```\n\n### Role-Based Access Control\n\n| ✅ |\n| Update Order Status | ❌ | ✅ | ❌ | ✅ |\n| Mark Delivered | ❌ | ❌ | ✅ | ❌ |\n| Create Promo | ❌ | ✅ | ❌ | ✅ |\n| Process Refund | ❌ | ✅ | ❌ | ✅ |\n\n---\n\n## Deployment\n\n### Option 1: Add to .gitignore\n2. **Use HTTPS in production** - Install SSL certificate\n3. **Validate all inputs** - Sanitize user data\n4. **Rate limiting** - Prevent brute force attacks\n5. **CORS configuration** - Only allow trusted origins\n6. **Password hashing** - Use bcrypt (already implemented)\n7. **JWT expiration** - Set reasonable token expiry\n8. **Database backups** - Regular automated backups\n9. **API versioning** - Use /api/v1/ prefix\n10. **Audit logging** - Track all sensitive operations\n\n---\n\n## Performance Optimization\n\n1. **Database indexing** - Already configured in schema\n2. **Connection pooling** -
